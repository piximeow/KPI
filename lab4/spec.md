# Специфікація: бізнес-процес «Оформлення й оплата замовлення»

## Процес
Деталізує UC2 «Оформити замовлення» з розширенням UC4 «Оплатити карткою» (lab2): від «Оформити» до відмови без адреси, закритої форми, номера замовлення або (картка) спрацювання таймера. Після інших відмов форма лишається, і Клієнт може знову натиснути «Підтвердити» (цикл); повтор після створення (друга вкладка) — новий екземпляр, його відхиляє REQ-08. Повідомлення шлюзу після `onPaymentTimeout` — окрема подія з тим самим правилом «`payment` не `pending` → `Accepted`, без змін» (REQ-15).

## Форма — activity-діаграма (PlantUML)
Activity показує ролі (доріжки), вибір, `fork`/`join` і сигнали; машина станів не показує, хто що робить, BPMN потребує окремого редактора й XML (`adr/0001`).

## Ролі (доріжки)
- **Клієнт** — дії в браузері.
- **Магазин** — сервіси й таймер lab3; повідомлення з Клієнтом названо викликами й результатами `CheckoutUI`.
- **Платіжний шлюз** — надсилає результат оплати (сама оплата на шлюзі — поза процесом).

## Кроки
1. «Оформити» → адреси; немає → `NoAddress` (REQ-02).
2. Цикл: «Підтвердити» → ліміт, форма, кошик (REQ-22) → транзакція: залишок і сума з `rollback` (REQ-07, 09), записи (REQ-03–05), для картки — таймер до `commit`; збій → `rollback` (REQ-06). Відмова → форма лишається.
3. Паралельно (лише Магазин): кошик (REQ-17) ∥ номер (REQ-18) або перенаправлення (REQ-10).
4. Картка: події по одній до `onPaymentTimeout` (REQ-11–16, 21).

## Повідомлення (назви з lab3)
| Хто → кому | Повідомлення | Якщо відповіді немає |
|---|---|---|
| Клієнт → Магазин | `openCheckout`, `confirmOrder` | форму закрито — нічого не створено |
| Магазин → Клієнт | `NoAddress`, форма, `Refused`, `order_id` | форма — чекає Клієнта (рядок вище); решта — кінець або повтор |
| Магазин → Клієнт | перенаправлення на шлюз | не чекає; `onPaymentTimeout` скасує |
| Магазин → Таймер | `schedule(payment_id, ordered_at + 15 хв)` | — (таймер спрацьовує завжди) |
| Шлюз → Магазин | `notifyPayment` | `onPaymentTimeout` скасує `order` |
| Магазин → Шлюз | `Accepted` / `Rejected` | повторне повідомлення — REQ-15 або REQ-21, без змін |
| Таймер → Магазин | `onPaymentTimeout` | спрацьовує завжди, до 16 хв (REQ-13) |

## Критерії прийняття
1. Activity-діаграма PlantUML; текст і SVG з того самого тексту.
2. Кожна дія досяжна й веде до кінця; кожен `if` має гілку на кожне значення.
3. ≥ 1 розгалуження і ≥ 1 `fork`/`join`; гілки `fork` містять лише дії Магазину — `join` не чекає зовнішнього учасника.
4. Кожне повідомлення — сигнал `>` у доріжці відправника з назвою й аргументами з lab3; події, яких процес чекає, — `<`; тексти відмов — у примітках; для кожного в таблиці сказано, що буде без відповіді.
5. Порядок перевірок, межі транзакції й момент запуску таймера — як у lab3; тексти відмов — дослівно з lab2.
6. `spec.md` і `DEFENSE.md` — до сторінки кожен.
