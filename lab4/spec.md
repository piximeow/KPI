# Специфікація: бізнес-процес «Оформлення й оплата замовлення»

## Процес
Деталізує UC2 «Оформити замовлення» з розширенням UC4 «Оплатити карткою» (lab2). Кінці: відмова без адреси, закрита форма, номер замовлення або (картка) таймер. Бізнес-результат картки — закриття `payment`; екземпляр закриває таймер. Після відмов форма лишається — цикл «Підтвердити»; повтор після створення відхиляє REQ-08, з другої вкладки — ні (кошик у браузері, `lab3/audit.md`). Повідомлення шлюзу після таймера — окрема подія за REQ-15.

## Форма — activity-діаграма (PlantUML)
Компроміс (`adr/0001`): BPMN точніший для «що прийде першим», але потребує редактора й XML; activity — короткий текст, як UC lab2; першу подію показано циклом з вибором.

## Ролі (доріжки) — як учасники lab3
- **Клієнт** — людина і `CheckoutUI` у браузері (там же кошик).
- **Магазин** — `CheckoutService`, `PaymentService`, `PaymentTimer` (таймер — частина Магазину).
- **Платіжний шлюз** — надсилає результат оплати (сама оплата на шлюзі — поза процесом).

## Кроки
1. `openCheckout` → адреси; немає → `NoAddress` (REQ-02).
2. Цикл: `confirmOrder` → ліміт, форма, кошик (REQ-22) → транзакція: залишок і сума з `rollback` (REQ-07, 09), записи (REQ-03–05), для картки — таймер до `commit`; збій → `rollback` (REQ-06) → `Refused` або `OrderCreated`.
3. Після `commit` паралельно: Клієнт — `clearCart` (REQ-17) ∥ номер (REQ-18) або перехід на шлюз (REQ-10); Магазин (картка) — події по одній до `onPaymentTimeout` (REQ-11–16, 21).

## Повідомлення (назви з lab3)
| Хто → кому | Повідомлення | Якщо відповіді немає |
|---|---|---|
| Клієнт → Магазин | `openCheckout`, `confirmOrder` | форму закрито — нічого не створено |
| Магазин → Клієнт | `NoAddress`, форма, `Refused`, `OrderCreated(order_id` + для картки `payment_id, payment_amount)` | форма чекає Клієнта; решта — кінець або повтор |
| Клієнт → Шлюз | перехід на сторінку оплати | не чекає; `onPaymentTimeout` скасує |
| Шлюз → Магазин | `notifyPayment` | `onPaymentTimeout` скасує `order` |
| Магазин → Шлюз | `Accepted` / `Rejected` | повтор — REQ-15 або REQ-21, без змін |
| у Магазині | `schedule`, `onPaymentTimeout` | до 16 хв; що таймер не губиться при перезапуску — припущення (`lab3/adr/0002`) |

## Критерії прийняття
1. Activity-діаграма PlantUML; текст і SVG з того самого тексту.
2. Кожна дія досяжна й веде до кінця; кожен `if` має гілку на кожне значення.
3. ≥ 1 розгалуження і ≥ 1 `fork`/`join`; `join` ніколи не чекає іншого учасника: гілка Клієнта після `commit` закінчується кінцем потоку (⊗), як і гілка Магазину для готівки — `stop` не обриває дій Клієнта.
4. Доріжки — учасники lab3; повідомлення — сигнал `>` відправника з назвою й аргументами з lab3, події, яких процес чекає, — `<`; для кожного сказано, що буде без відповіді.
5. Порядок перевірок, межі транзакції й запуск таймера — як у lab3; тексти відмов — дослівно з lab2.
6. Аудит: виправлені розбіжності «було → стало» і залишкові розбіжності з lab2/lab3.
7. `spec.md` і `DEFENSE.md` — до сторінки кожен.
