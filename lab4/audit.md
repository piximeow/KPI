# Аудит процесу

Відповіді чату й рішення за кожною знахідкою — `ai/prompts.md` (П1, П2). Кожне виправлення спершу змінювало spec, потім діаграму.

## 1. Переходи, досяжність, умови
- **Кінці (4):** `NoAddress`; Клієнт закрив форму; `cash_on_delivery` після `join`; для картки — після `onPaymentTimeout`. Кожен досяжний від `start`.
- **Відмови після «Підтвердити»** (REQ-20, 19, 08, 07, 09, 06) повертають до форми — дій без виходу немає.
- **Кожен `if`** має гілку на кожне значення: адреса є/немає, натиснув/закрив, умова відмови так/ні, бракує/ні, `card`/ні, збій/ні, спосіб оплати, подія шлюзу/таймера, підпис, `pending`, результат `succeeded`/`failed`.
- **Досяжність кожної гілки циклу:** недійсний підпис — S05 рядок 4; не `pending` — S05 рядки 1–3; успіх — S02; відмова банку — S03 рядок 1; таймер з `pending` — S03 рядок 3; таймер після успіху — S03 рядок 4.
- **Завершення циклу:** вихід лише після `onPaymentTimeout`, який приходить завжди (таймер поставлено до `commit`) — `adr/0002`.

## 2. Паралельні гілки
Два `fork`/`join` після `commit`: `clearCart` ∥ `order_id` і `clearCart` ∥ перенаправлення. Обидві гілки — дії Магазину без очікування, тож `join` завжди відбувається. Перенаправлення не чекає шлюзу: його відповідь приходить у цикл.

## 3. Повідомлення
| Відправник → отримувач | Повідомлення | Якщо відповіді немає |
|---|---|---|
| Клієнт → Магазин | `openCheckout`, `confirmOrder` | форму закрито — нічого не створено |
| Магазин → Клієнт | `NoAddress`, форма, `Refused`, `order_id` | форма чекає Клієнта; решта — кінець або повтор |
| Магазин → Шлюз | перенаправлення | `onPaymentTimeout` скасує |
| Магазин → Таймер | `schedule` | — (таймер у Магазині) |
| Шлюз → Магазин | `notifyPayment` | `onPaymentTimeout` скасує |
| Магазин → Шлюз | `Accepted` / `Rejected` | повтор шлюзу — REQ-15, без змін |
| Таймер → Магазин | `onPaymentTimeout` | приходить завжди |
