# Матриця трасування «вимога ↔ сценарій / UC»

## Непокрите й обґрунтування

| Елемент | Чому не покрито сценарієм |
|---------|---------------------------|
| REQ-08a (картковий `payment` стає `failed` через `T_CARD_FINAL`) | це запобіжник проти «вічного» `pending`, коли шлюз мовчить, а не шлях потреби відвідувача: на той час замовлення вже скасоване (REQ-08). Перевіряється тестом зі зсунутим годинником (NFR-04). |
| REQ-25 (пріоритет перевірок V1–V5) | правило вибору між уже описаними відмовами; кожна з перевірок має свій сценарій (S12, S6, S11, S8, S7). Окремий сценарій з кількома помилками одночасно не дає нового шляху потреби. |
| UC1–UC4, UC8–UC12 | глибина роботи — один прецедент (UC5). Ці UC показані на діаграмі для контексту й меж, вимоги до них не пишуться. |
| UC6 | включається лише в UC5 і покритий повністю (REQ-11, REQ-12, REQ-15, REQ-23). |
| UC7 | розписаний лише як розширення UC5 (REQ-03c–REQ-08a, REQ-17, REQ-20a, REQ-22, REQ-24); вхід з UC9 не розписаний. |
