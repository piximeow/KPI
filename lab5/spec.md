# Специфікація: компонентна модель онлайн-магазину (UC2 + UC4)

## Намір
Показати архітектуру, яка реалізує UC2 «Оформити замовлення» з UC4 «Оплатити карткою»: компоненти, їхні provided/required-інтерфейси, залежності, межу системи й зовнішні інтеграції. Компоненти — ті самі учасники, що в sequence-діаграмах lab3 і доріжках процесу lab4; дані — модель lab1.

## Модулі
| Шар | Компонент | Відповідає |
|---|---|---|
| UI | `CheckoutUI` (браузер) | форма, кошик, повідомлення, перехід на шлюз (REQ-01, 02, 10, 17–19) |
| API | `CheckoutAPI` | HTTP-запити UI: `openCheckout`, `confirmOrder` → `IOrderCreation` |
| API | `PaymentWebhook` | HTTP-запит шлюзу `notifyPayment` → `IPaymentEvents`, відповідь `Accepted`/`Rejected` |
| Сервіси | `CheckoutService` | перевірки REQ-22, транзакція створення, постановка таймера (REQ-03–09, 13, 20) |
| Сервіси | `PaymentService` | підпис, події по одному, статуси, повернення залишку (REQ-11–16, 21) |
| Сервіси | `PaymentTimer` | спрацювання через 15 хв від `ordered_at` (REQ-13) |
| Data Access | репозиторії `customer`/`address`, `product`, `order`/`order_item`, `payment` | читання й запис сутностей lab1, блокування рядків |
| БД | `ShopDB` | таблиці lab1 |

## Зовнішні інтеграції
- **Платіжний шлюз** — сторінка оплати (Клієнт переходить на неї) і `notifyPayment` з підписом HMAC-SHA256 (NFR-05).
- Вхід Клієнта (облікові дані) — поза моделлю lab1 і поза UC2; email/SMS вимоги не задають — на діаграмі немає.

## Межа системи
Усередині — `CheckoutUI`, API, сервіси, Data Access, `ShopDB`. Зовні — Клієнт (людина) і Платіжний шлюз; обмін через межу — лише через інтерфейси API і перехід браузера на шлюз (HTTPS, NFR-05).

## Критерії прийняття
1. UML Component Diagram у PlantUML; текст і SVG з того самого тексту.
2. Кожен компонент має provided-інтерфейс, а кожна залежність — required-інтерфейс іншого компонента; інтерфейси названо операціями з lab3.
3. Межа системи — рамка; зовнішні інтеграції — поза нею.
4. Кожен компонент і залежність трасується до lab1 (дані), lab2 (вимоги), lab3 (взаємодія) і lab4 (процес); нічого, чого там немає.
5. Залежності йдуть лише згори вниз (UI → API → сервіси → Data Access → БД), циклів немає.
6. `spec.md` і `DEFENSE.md` — до сторінки кожен.
